# RH56F1 양팔 정지 추종 오차 실험

작성일: 2026-11-07. 대상은 OpenArm 양팔 + Inspire RH56F1이다. 이 문서는 구현 사양과 실험 절차이며, 실기 A–G의 수행 또는 1 mm 달성을 보고하는 문서가 아니다. 오른팔 자세 6개와 현재 장면의 왼팔 홈 스냅샷은 저장되어 있다. 오른팔의 손끝 목표를 좌우 대칭 변환해 왼팔 경로를 오프라인 생성했으며, 실기 실행 전에는 캡처된 홈·주변 장면·PD 상태를 다시 확인한다. 테이블 접촉 자세나 `bc05`를 시작 자세로 자동 선택하지 않는다.

## 목표와 해석

계획된 경로 종료 시각을 0으로 두고, 사용자 목표각과 실측각으로 각각 계산한 손끝 FK 위치 차이가 3초 이내 1 mm 이하에 진입한 뒤 10초 연속 유지되는지 평가한다. 양쪽 FK에 **동일 시각의 같은 손 실측 관절값**을 사용한다. 팔 관절만 목표/실측으로 바꾼다. 프레임과 손끝 링크는 실행 manifest에 고정한다.

이는 모델 안의 추종 성능이다. 실제 손끝 위치와 FK의 차이, 관절 영점, 링크 형상·탄성, 카메라 외부 파라미터 오차는 별도 결과다. 모델상 1 mm 통과를 실제 공간 1 mm 정확도로 표현하지 않는다. 여러 관절 오차가 손끝에서 상쇄되는 경우를 구분하기 위해 관절별 절대 오차 0.1° 이하와 유지 구간 peak-to-peak 0.05° 이하도 함께 판정한다.

이번 범위는 계측, 반복 실험, 오프라인 분석, 실행 게인 일치 검사, 기본 비활성 중력 보정·마찰 보정·제한 적분이다. 고속 궤적 제어, DOB, LuGre, 관절 영점 변경, 테이블·로봇 USD 수정은 제외한다. 기본 운영 프로파일은 변경하지 않는다.

## 계측과 데이터 계약

도구는 `deploy/policy_control/tools/stationary_tracking.py`의 `capture`, `prepare`, `run`, `analyze`다. `capture`는 구독만 하고, `prepare`는 경로·한계·충돌·설정 검사만 한다. `run`은 `--execute`가 없으면 명령을 발행하지 않는다. 실행 시에도 기존 PD 목표/episode 경로를 이용하며 직접 CAN 제어나 별도 PD 루프를 만들지 않는다. `analyze`는 저장 데이터만 읽는다.

산출물은 `logs/analysis/stationary_tracking_1107/` 아래 새 실행 디렉터리에 저장한다. 기존 로그·보고서를 덮어쓰지 않는다. 실행마다 `manifest.json`, `events.jsonl`, `summary.json`, `report.md`, 그래프를 보관한다. 중단된 실행도 원시 기록과 중단 사유를 남긴다.

manifest 필수 정보:

- 코드 commit 및 dirty 상태, URDF·설정 파일 경로와 SHA-256, 관절 순서와 단위.
- 기대/실행 Kp·Kd, 학습 계약 게인과 차이 허용 근거, 생성된 robot_description과 드라이버 기동 증거.
- 중력·마찰·적분 ON/OFF와 모든 계수, 유효 토크 한계, 손 고정 자세·손끝 링크·FK 프레임.
- ROS domain, episode, 실험 단계·후보·반복·접근 방향, 경로 종료 시각, 명령 발행 여부.
- 식별용/보류 자세 ID, 제외 사유, 안전/보호 상태, 센서 분해능과 시간 정렬 설정.

다음 네 값은 서로 다른 신호로 보관한다: **사용자 목표**, **제한기를 지난 PD 목표**, **최종 모터 위치 명령**, **실측각**. `applied.effort`의 기존 의미(송출 FF 토크)는 바꾸지 않는다. 이것을 모터 PD까지 포함한 전체 토크로 해석하지 않는다.

별도 `/policy_control/pd_right/diagnostics` String JSON에는 같은 제어 tick의 위 값, 실측/명령 속도, 모델 중력·추가 중력·마찰·적분·요청·FF·모터 PD·추정 전체 토크, 실측 토크, 온도, 접촉·stale·보호·제한기 상태, episode를 담는다. `torque_estimated_total = Kp·(motor_position−measured) + Kd·(motor_velocity−velocity) + torque_feedforward`이다. 이는 전류/토크 센서 실측과 구분한다. 미수신 상태는 0이 아닌 누락/unknown으로 표시한다.

원본 timestamp와 수신 시각을 모두 보관한다. 관절은 배열 순서가 아니라 이름으로 정렬한다. 과거 로그의 서로 다른 토픽을 대응시킬 때 최대 시간차는 20 ms다. 대응 실패·누락 비율, 시간 기준, 원본/수신 지연을 보고하고 긴 공백을 보간해 합격시키지 않는다. 새 진단은 동일 tick 묶음을 우선한다. 접촉 관측이 없으면 비접촉으로 추정하지 않는다.

## 실행 게인과 보상

하드웨어 Kp·Kd는 bringup 시 주입된다. YAML만 수정한 뒤 적용됐다고 판단하지 않는다. 실험 블록 사이에 승인된 재기동으로 바꾸고, 오른팔 전용 `arm_gains_override`만 적용한다. 왼팔 게인과 URDF 자산은 바꾸지 않는다. 생성 robot_description의 하드웨어 게인과 PD가 기대하는 게인을 대조하며 불일치/증거 결손이면 실험 engage를 거부한다. 계약 차이 허용은 `gains.experiment_profile: stationary_tracking`에 한정한다. 일반 정책의 기존 게이트를 완화하지 않는다.

보상은 시작 시 설정을 고정하고 기존 PD tick 안에서 계산한다. 세 기능 기본값은 OFF다.

\[
\tau_{ff}=\hat g(q)+\Delta\hat g(q)+F_c\tanh(\dot q/v_s)+F_v\dot q+F_o+\tau_I+\tau_{request}.
\]

| 기능 | 식별/동작 | 제한 |
|---|---|---|
| 추가 중력 | 손 자세를 고정하고 말단 payload의 질량·1차 모멘트 보정 `[Δm, Δmx, Δmy, Δmz]`를 선형 회귀 | 마지막 팔 링크 프레임 사용. rank·특이값·조건수와 식별 가능한 조합 보고. 보류 자세 토크 예측이 개선될 때만 채택 |
| 마찰 | 정·역방향 저속 데이터에서 `Fc·tanh(v/vs)+Fv·v+Fo` | 계수 초기값 0, `vs > 0`. 속도 0에서 정지 마찰 완전 보상을 주장하지 않음 |
| 제한 적분 | PD 목표−실측 오차를 토크로 적분 | 위치 목표를 계속 이동시키지 않음. 정상·비접촉·정착 때만 갱신; 목표 이동, stale, 보호 때 갱신 중지 |

다른 링크의 중력 오차까지 손 질량에 흡수할 수 있으므로 학습 오차만으로 payload를 채택하지 않는다. 정·역 토크 평균·차이는 저가속·동일 위치 구간에서만 사용한다. 평균에는 방향 독립 편향도 포함되므로 순수 중력의 직접 측정이 아니다. 비대칭 마찰·배선 이력으로 보류 예측이 맞지 않으면 모델을 기각한다.

적분 정지 deadband는 0.03°, 재개는 0.06°로 시작한다. deadband 안에서는 기존 적분을 보존한다. 센서 유효 양자화 간격과 비교해 결과에 기록한다. 초기 상한은 J1–J4 1 N·m / J5–J7 0.3 N·m, 변화율은 0.2 / 0.05 N·m/s다. 모터 PD까지 포함한 전체 추정 토크에서 유효 토크 한계 여유를 구하고 추가 토크를 제한한다. 포화 방향의 오차를 더 쌓지 않는다. 기존 유효 한계가 더 작으면 그것을 따른다. 실패 시 자동으로 상한을 확대하지 않는다.

새 목표·새 episode의 이전 적분은 학습값으로 재사용하지 않고 기존 블렌딩 시간에 맞춰 제거한다. 접촉·stale·중단에서는 기존 안전 전환이 우선한다. 제거 중 출력 연속성을 fake에서 검사한다. 조그 연속 보정·home 정착 적분·기존 droop 적분과 새 적분을 중복 활성화하는 구성은 거부한다.

## 실험 준비와 A–G 순서

오른팔 6개 자세는 구독 전용 capture로 저장되어 있으며, 첫 3개는 조정용, 나머지 3개는 보류 검증용으로 분리되어 있다. 왼팔의 현재 홈 자세와 주변 장면도 구독 전용으로 저장했다. 왼팔 목표는 오른팔 손끝 위치를 base Y=0 평면에 대해 대칭시킨 뒤 측정된 왼손 자세를 고정해 IK로 생성한다. 좌우 관절각을 단순 부호 반전해 경로로 쓰지 않는다.

현재 왼팔 오프라인 계획은 다음과 같다. 두 계획 모두 63개 경로가 시작 홈 접근, 목표 경로, 목표에서 15초 정지 후 홈 복귀까지 충돌 검사에 통과했고, 대칭 손끝 IK 잔차는 0.0013 mm 이하이다. 나머지 63개 후보는 기존 충돌 검사에서 제외되어 자동 실행하지 않는다. 계획 생성과 dry run은 명령 0개로 끝났다.

- A 기준선 계획: `logs/analysis/stationary_tracking_1107/runs/left_mirror_prepare_A_v4/plan.json`
- G 보류 검증 계획: `logs/analysis/stationary_tracking_1107/runs/left_mirror_prepare_G_v3/plan.json`
- 기준 입력: `logs/analysis/stationary_tracking_1107/inputs/right_pose_set_v1/poses.json` 및 `scene_complete_attention_left_home.json`
- A 무발행 dry run: `runs/left_trial_dry_run_v3/`, 선택 trial `A_left_mirror_fit_01_j1_-1_r1`

각 trial은 캡처된 왼팔 홈과 실측 주변 장면이 검사 기준과 일치할 때만 실행 가능하다. 현재 계획은 오른팔이 캡처된 attention 자세에 있는 장면을 사용하므로, 오른팔이 움직였거나 홈 자세가 달라졌으면 최신 양팔 scene을 캡처해 A와 G를 다시 준비해야 한다. 단계별 실행 명령은 아래와 같다.

```bash
ROS_DOMAIN_ID=50 python3 deploy/policy_control/tools/stationary_tracking.py run \
  --plan logs/analysis/stationary_tracking_1107/runs/left_mirror_prepare_A_v4/plan.json \
  --trial A_left_mirror_fit_01_j1_-1_r1 \
  --out logs/analysis/stationary_tracking_1107/runs/left_A_fit01_j1_neg_r1 --execute
```

G 단계에서는 `left_mirror_prepare_G_v3/plan.json`의 trial ID를 골라 같은 형식으로 실행한다. 무발행 실행 확인은 다음과 같이 할 수 있다.

```bash
ROS_DOMAIN_ID=50 python3 deploy/policy_control/tools/stationary_tracking.py run \
  --plan logs/analysis/stationary_tracking_1107/runs/left_mirror_prepare_G_v3/plan.json \
  --trial G_left_mirror_holdout_01_j1_-1_r1 \
  --out logs/analysis/stationary_tracking_1107/runs/left_G_holdout_dry_run
```

실험 발행용 왼팔 PD 설정 사본은 `deploy/policy_control/config/pd_rh56f1_stationary_left_exec.yaml`이며 무발행 원본과 `execute`만 다르다. `--execute` 전에는 왼팔 PD가 `TRACKING`이며 runtime gain 검증을 통과해야 한다. 조그의 `실기 발행`이 정상 작동하면 이미 이 PD 조건을 만족하므로 다시 PD를 engage하지 않는다. 현재 실측 왼팔 각도는 저장된 홈과 0.002 rad 이내여야 한다. 자동 trial과 조그는 같은 `/policy_control/joint_target`을 사용하므로 실험 시작 전 조그 발행을 해제하고 jog publisher를 종료한다. 실행은 기존 PD 목표/episode 인터페이스만 사용하며, 경로 종료 후 홈으로 복귀한다. 본 문서 작성 시점에는 이 실기 명령을 발행하지 않았다.

## 합격 판정과 후보 선택

유효한 실행에서 경로 종료부터 3초 이내의 시각 `t_enter`를 찾고, `[t_enter, t_enter+10 s]` 동안 손끝 위치 차이 ≤1 mm가 연속 유지되어야 한다. 기록 종료가 일찍 오거나 20 ms를 넘는 필수 대응 공백이 있으면 연속 유지가 입증되지 않는다. 관절 절대 오차 ≤0.1°와 유지 중 peak-to-peak ≤0.05°도 별도 flag로 보고한다. 손끝 기준만 통과하고 관절 기준이 실패하면 상쇄 가능성을 표시한다.

접촉, 보호 동작, 평가 중 목표 변경, 필수 상태 결손이 있는 실행은 합격 평가에서 제외하고 원인을 기록한다. 전 구간 오차 곡선, 정착 시간, 관절별 오버슈트, 유지 중 변동, 추가 보상 토크 RMS, 실측 토크·온도 최대값을 보고한다. 실제 손끝−FK 기구학 오차는 별도 항목에 둔다.

모든 기준을 통과한 조합 중 **최대 Kp 배율이 가장 낮은 후보**, 동률이면 **추가 보상 토크 RMS가 가장 작은 후보**를 선택한다. 보류 검증 실패 후보를 최종 채택하지 않는다. 통과 후보가 없으면 달성한 오차·유지 시간과 남은 원인 가설을 보고하며 자동 재튜닝이나 토크 상한 증가는 하지 않는다.

## 중단·복구·원복

1. 기존 과열·추종·토크 보호, 접촉, stale, 경로/게인 불일치가 발생하면 해당 실행을 중단하고 다음 후보로 자동 진행하지 않는다. 원시 기록과 마지막 명령·실측·안전 사유를 보존한다.
2. 자동 안전 HOLD와 기존 보호가 우선한다. 실험 도구가 강제로 해제하거나 드라이버를 kill하지 않는다. 물리적 받침·장애물·발열·CAN 상태는 운영자가 확인한다.
3. 실기 ROS domain 50에서 움직임·힘을 내는 새 명령, 드라이버/PD 기동·종료는 `sim2real/CLAUDE.md`의 명령별 승인 규칙을 따른다. 중단된 연속 실행의 승인을 재사용하지 않는다. fake domain 97/99는 이 실기 승인 규칙 대상이 아니다.
4. 복구는 원인 확인 → 안전 시작 자세·손 자세 확인 → 새 episode/새 run → 별도 승인 순서다. 중단 데이터는 지우지 않는다.
5. 원복은 운영자가 기존 유지·블렌딩 경로를 사용하고, 다음 승인된 bringup에서 override를 제거하여 원래 게인을 복원한다. 보상 OFF의 원본 운영 프로파일로 돌아간 뒤 생성 XML/상태를 재검사한다. 갑작스런 힘 해제를 원복 수단으로 사용하지 않는다.

실기 A–G 원시 기록과 최종 채택 설정은 아직 없다. fake/단위 테스트와 오프라인 경로 검사는 코드·모델 검증이며 실기 안정성이나 실제 공간 정확도의 증명이 아니다. 구현·검증 명령과 남은 항목은 [구현 계획 및 원장](../superpowers/plans/2026-11-07_stationary_tracking_compensation.md)에 기록한다.

## 2026-11-07 재개: 왼팔 실기 수집

사용자는 이번 실험 범위의 반복 승인 질문 없이 기동·제어 전환·홈 및 수집을 계속 진행하도록 명시했다. 이 승인은 다른 작업의 자동 실행으로 확대하지 않는다. 빈손, 이동 공간 비어 있음, 테이블 비접촉을 사용자에게 확인받았다.
