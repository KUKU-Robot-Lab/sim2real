# 11.10 팔 추종 개선 — 실기 진행안

## 바뀐 것 (커밋 107110c + 이번 설정)
- 코드: pd_arm.py `qd_target_diff`(q̇* = Δq*/Δt), pd_law.py `fric_ff`(마찰 전향). 설정 키가 없으면 꺼져서 이전과 같다.
- **T1 (미션 기본, 사용자 "속도 상한은 풀어야")**: `pd_rh56f1.yaml`·`pd_rh56f1_exec.yaml` 에
  `vel_ff_cap 0.0 → 0.5` + `qd_target_diff {max_dt 0.1, hold_sec 0.07}`. 예측 손끝 z 차이 −19 %.
- **T2 (따로 둔 사본)**: `config/tracking_1110/pd_rh56f1{,_exec}_T2.yaml` = T1 + `fric_ff`(적합값 절반). 예측 −35 %.
- T3(j5~j7 Kp 20/30)·vel_ff_cap 2.0 은 아직 설정 파일 없음. T2 결과를 보고 만든다.

## 실기 순서 (단계마다 사용자 승인)
1. **공중 확인(컵 없음)**: T1 로 미션 기동 → grasp_s_right 접근 구간만. 볼 것: 진동·소음 없음, effort_cap 근접 없음,
   `/policy_control/pd_*/status` 의 qd 명령이 0 이 아님, 손끝 명령−실측 z 차이(bag).
2. **grasp_s_right / left 각 3회 (T1)**: 접근 최저 손끝 높이(탁자 위 mm), 탁자 접촉 여부, 성공률. 기준선: 손끝 최저 39.7~42.0 mm, 명령−실측 20~43 mm.
3. 1·2 가 안전하면 **T2** 로 바꿔 같은 3회씩(미션 yaml 의 pd_exec 경로를 T2 사본으로). 비교표: 기준선 / T1 / T2.
4. 차이가 예측(−19 % / −35 %)보다 작으면 T3(Kp) 설정을 만들고 다시 승인.
- 정책 주기 31~41 Hz 저하(명령 속도가 sim 의 2/3)는 별개 문제 — 실험기에서 최적화 중. 이번 비교에서는 주기도 같이 기록한다.
- 중단 기준: 진동, 관절 effort 경고, 손이 탁자에 닿음 → 즉시 hold.
